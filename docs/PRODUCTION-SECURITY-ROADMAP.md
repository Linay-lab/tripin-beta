# TRIPIN 正式多人版：安全架構與上線門檻

> 2026-10-28。此文件是規劃與驗收標準，不代表正式後端已完成。現有 GitHub Pages Beta 不得用於真實多人帳號或敏感資料。

## 現況與主要風險

1. **GitHub Pages 是靜態前端**，不能在前端保管伺服器密鑰，也不能代替後端授權。
2. Beta 的登入／註冊是**本機展示流程**，使用 sessionStorage；不是真正的身份驗證，沒有雲端密碼重設。
3. 旅行、購物、GPS 商店等資料目前放在 localStorage；不具備跨裝置同步、多人隔離、可靠備份或並發控制。
4. Google Apps Script 回饋目前可從瀏覽器直接呼叫；部署網址是公開入口，須另外審查匿名濫用、速率限制、表單輸入、儲存權限及回應內容。不能把 Apps Script URL 當秘密。
5. GPS 提醒需要前景頁面與定位權限；不得宣稱 iOS/Android 背景推播已完成。
6. 自動測試使用模擬 GPS、攔截回饋請求及隔離資料，不能等同真實手機定位測試、滲透測試或正式容量測試。

## 建議正式架構（先規劃，尚未部署）

- 前端：保留 TRIPIN 設計，將本機展示登入與資料存取改接真正的後端 API；逐步遷移，不直接覆蓋 Beta。
- 身份驗證：使用受維護的 Auth 服務，支援電子郵件驗證、重設密碼、工作階段撤銷；伺服器驗證 token，不信任前端傳來的 user_id。
- 資料庫：PostgreSQL 等有備份、交易及存取控制的資料庫。每筆旅行、商品、行程、商店及錢包資料都有 owner_id；所有讀寫必須驗證登入者的擁有權（若使用 Supabase，必須開啟並測試 RLS）。
- 重要規則：不要把 service-role key、資料庫密碼或其他伺服器秘密放進 GitHub Pages 或前端 JS。公開金鑰也須限制能力及網域，不能代替 RLS。
- 回饋：後端驗證輸入、限制請求頻率、防垃圾訊息；避免公開寫入試算表的權限；對外不回傳內部錯誤細節。
- 隱私：明確取得定位權限，只儲存必要資訊；提供資料匯出／刪除、隱私政策及保存期限。
- 備份：定期自動備份、測試還原；建立 schema migration 與回滾方案。

## 正式上線前的必過驗收

- [ ] 兩個不同帳號的旅行、商品、錢包及商店資料彼此不可讀寫，包含直接呼叫 API 嘗試跨帳號存取。
- [ ] 未登入、過期 token、偽造 owner_id 都被伺服器拒絕。
- [ ] 新增、修改、刪除與重新登入／跨裝置同步正確；失敗時有清楚提示且不遺失資料。
- [ ] 回饋端點驗證輸入、限流、防濫用；測試不寫入真實回饋表。
- [ ] 安全依賴檢查、權限／RLS 自動化測試、XSS／CSRF／注入防護檢查完成。
- [ ] 實體 iPhone 與 Android 測試定位授權、前景 GPS、離線與省電模式；背景提醒若未開發則明確標示限制。
- [ ] 以預期並發量做後端負載、壓力、恢復與資料庫連線測試，並監控錯誤率與延遲。
- [ ] 隱私政策、資料刪除、備份還原、緊急停用與事故處理流程完成。

## 版本界線

- `Linay-lab/tripin-beta`：公開的獨立功能展示／測試站。
- `Linay-lab/travel-studio-preview`：原始開發及測試來源；不因本文件自動合併或部署。
- 正式多人版：需要另外規劃後端與資料庫，不得以「三瀏覽器綠燈」取代安全驗收。
