# iOS／Android 背景購物提醒實作規劃
更新：2026-11-01。狀態：設計完成，原生 App 尚未實作或實機驗收；不得標示背景提醒已完成。

## 產品範圍
網頁目前只承諾頁面可執行時的定位提醒。App 背景版採原生地理圍欄與本機通知；不以網頁計時器、持續 GPS 輪詢或推播取代裝置端定位。建議先做原生能力驗證，再決定跨平台 UI 框架與橋接套件；現有 Next.js 網站保留。以下數值為設計候選，並非已通過實測的承諾。

| 情境 | 目標行為／限制 |
| --- | --- |
| 開啟 App | 位置可用時評估未購買清單，與背景共用通知去重 |
| 切換別的 App、鎖定螢幕 | 權限與系統條件允許時由原生圍欄觸發；不能保證到線立即通知 |
| 系統回收程序 | 原生回呼重新載入帳號、清單與去重狀態；不能依賴記憶體中的 JS |
| 使用者強制停止或滑掉 App | 分 OS／版本實測；不宣稱必定有效。Android 文件明列部分強制關閉／重設會移除圍欄 |
| 重新開機 | Android 重新登記；iOS 依採用 API 恢復監控，重開機首次解鎖前不保證有效 |
| 關閉定位、通知或背景權限 | 清楚顯示暫停原因，保留清單，不假顯示「已啟用」 |
| 無網路 | 已有本機快照可提醒；其他裝置剛標記購買的狀態可能尚未同步，必須揭露 |

## 原生端設計
iOS：以 Core Location 地理條件監控為候選，搭配 UserNotifications；依最低支援系統確認 CLMonitor／相容 API 與授權生命週期。官方文件同時最多 20 個條件，規劃按旅行啟用狀態、行程日期與距離排序，只登記最重要的 20 家；超額商店顯示尚未監控。冷啟動重建同一監控識別，確認通知與定位授權。不要將「系統嘗試喚起」寫成每次保證喚起。

Android：Google Play services GeofencingClient + PendingIntent/BroadcastReceiver + NotificationManager。最多每 App 每裝置使用者 100 個圍欄；缺少 Google Play services 的裝置第一版顯示不支援背景圍欄，不靜默失效。背景定位、精確位置及通知權限分開檢查與漸進請求；Android 13+ 通知另需 POST_NOTIFICATIONS。回呼處理須在允許的生命週期內完成，本機資料優先，不能等網路才決定提醒。開機、升級、重新登入與服務重設後比對並重新登記。

權限流程：使用者主動啟用 → 解釋靠近商店的用途 → 前景定位 → 個別平台要求的背景授權 → 通知授權。拒絕時提供前景提醒與系統設定入口，避免反覆強迫彈窗。需另完成商店審查所需背景定位用途與隱私揭露。

## 共用資料契約與處理
1. 用穩定 storeId／placeId 分店；同名不同分店不可合併。每商品可以指定唯一購買分店；沒有有效座標的商店標示待補，不登記圍欄。
2. 快照包含 accountId、tripId、storeId、商品 ID／名稱／購買狀態／版本、商店座標、設定版本、同步時間與帳號世代。位置軌跡預設不送伺服器。
3. 圍欄進入 → 核對目前 accountId／世代、啟用設定、快照完整性 → 重新查本機最新未購買商品 → 同店合併一則通知。空清單直接取消該店待送與已顯示通知。
4. 以本機交易保存每帳號／旅行／商店的進出狀態與最後嘗試時間；前景與背景共用同一資料庫和固定通知 ID。併發事件只能保留一次有效預約。
5. 通知 API 與資料庫沒有跨系統原子交易：先記預約可能漏提醒，先通知可能重複。第一版偏向避免重複，使用固定通知 ID 取代同店舊通知，重啟後核對待送／已顯示狀態；明列異常窗口，不宣稱 exactly once。
6. 可設定距離候選 150／300／500 公尺（預設 300）及冷卻候選 60 分鐘。以離開後再次進入且超過冷卻才重新提醒；邊界抖動採退出緩衝，最終值需步行／開車實測。系統背景延遲與精度可能大於使用者選定距離。
7. 完成購買、刪除商品、停用旅行、變更距離後立即重新計算並更新監控；全部買完移除商店圍欄。通知點擊後再查最新清單，避免打開過期商品。
8. 登出／切換帳號先提高世代、使舊回呼失效、停用圍欄與清理通知／快照；清理未完成時新帳號背景監控維持停用。操作成功後才顯示啟用。
9. 鎖定畫面預設文案「附近有尚未完成的購物清單」；使用者可選擇顯示店名／商品，避免預設暴露送禮對象、備註或預算。錯誤與統計不記錄 JWT、精確路徑或商品內容。

## 實作工作順序
- A：獨立 App 分支與最小原生原型，只用合成商店與清單，驗證鎖定／背景／程序回收。
- B：共用純邏輯（分店合併、購買排除、冷卻、配額排序）及可重現單元測試；不混入 Google Apps Script 回饋改動。
- C：原生本機交易、前景／背景互斥與帳號切換清理；網路同步沿用現有登入身分，不引入管理員金鑰。
- D：可見的權限／暫停／監控店家狀態頁，通知深連結與隱私設定。
- E：真機矩陣驗證，再產生簽章測試安裝檔。開發者帳號、簽章設備與發佈權限未確認前，不承諾交付日或商店上架。

## 驗收矩陣（目前全部待原生實作／真機測試）
至少 iPhone 與兩個 Android 廠牌，記錄 OS／機型／App 版號、權限、低電量與網路狀態；每情境重複至少三次，保存預期／實際時間與合成 storeId，不保存私人軌跡。
- 鎖屏 15／60 分鐘後進出店家；一般背景與系統程序回收分開測。
- 強制停止、從最近使用滑掉、重開機首次解鎖前／後分開記錄。
- 同店三件未買一件已買 → 一則三件；不同分店不誤合併；全買完無通知。
- 連續重複圍欄事件、前景與背景同時進入、邊界抖動、冷卻前／後再次進入。
- 登出期間延遲回呼、A 切 B、通知點擊時商品被刪；不能顯示前帳號內容。
- 飛航、無網路、同步失敗、另一裝置修改購買狀態；驗證過期快照提示。
- 拒絕與撤回各權限、只給大概位置、關閉通知頻道、低耗電／省電限制。
- 21 家 iOS／101 家 Android 商店；超額提示、排序與旅行變動後輪替。
- 同路線無監控對照電量與背景版電量，記錄到達至通知的延遲分布；未實測前不給耗電或即時性保證。
